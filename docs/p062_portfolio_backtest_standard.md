# P0.6.2 时点严格的组合回测标准

> 本文件冻结 P0.6.2 的历史标准。新运行沿用本文件的事件时钟与组合会计，
> 交易冲击、费用诊断和小额订单规则升级为
> `docs/p063_execution_cost_standard.md`，产物 schema 为 P0.6.3。

## 目标与范围

P0.6.2 将 P0.5 可交易性矩阵与 P0.6.1 执行、费用、容量和会计规则串成逐日组合回测。它解决“按当时可知信息产生目标、下单、成交、结算、估值和处理公司行为”，不负责产生 alpha 信号。

适用边界是现金 A 股、多头、日线执行、周频或更低频调仓。不将日线假装成逐笔撮合，也不声称可以证明集合竞价排队顺序。

## 事件时钟

每个交易日按固定顺序处理：

1. 进入新交易日，上一日买入股份转为可卖；
2. 开盘前处理送转、退市现金结算等生效事件；
3. 除息日开盘确认现金股息应收款，付息日再将应收款转入现金；
4. 激活已冻结且 `decision_at < execution_event_at` 的目标权重；
5. 使用开盘前已知的未复权前收价与当前账本生成净订单；
6. 依次执行卖单和买单，应用 T+1、涨跌停、停牌、申报单位、现金、容量、滑点和费用约束；
7. 使用未复权收盘价估值；停牌可携带上一个有效收盘价以完成交易账本，超过冻结的最大陈旧交易日数后必须同时产生末价上界与零价下界；
8. 股权登记日收盘冻结现金分红权益数量。

组合净值勾稽为：

```text
NAV = cash + sum(raw_close * total_quantity) + dividend_receivable
```

应收股息只进入 NAV，在付息前不能被当作可用现金买股。

## 长停牌估值上下界

`max_stale_valuation_sessions` 默认仍为 20，未被放宽。对陈旧期超过该上限的正持仓，每个执行情景、每个交易日必须同时输出：

- `stale_at_last_close`：按最后可观察未复权收盘价计量，作为估值上界；
- `stale_at_zero`：将超限持仓的当日末价市值减记为零，作为保守下界。

两个估值情景共用同一套订单、成交、费用、现金和持仓账本，只是收盘 NAV 的覆盖层，不允许用下界 NAV 反向改变当日或后续订单。区间宽度定义为：

```text
bound_width_pp = stale_market_value_at_last_close / nav_at_last_close * 100
```

默认 `max_stale_valuation_nav_bound_pp = 2.0`。两个端点缺一、与持仓账本不勾稽，或任一执行情景、任一日的宽度超过 2 个百分点，均阻止晋级。通过只证明该不确定性已完整上报且有界，不表示两个端点任一是公允价值模型。

## 目标权重和未成交订单

目标文件至少包含 `trade_date`、`instrument_id`、`target_weight`、`decision_at`。目标只允许多头，权重之和不得超过 `1 - cash_buffer_fraction`，默认现金缓冲为 2%。

目标在当日全部成交或剩余差额低于申报单位后结束，不会将周频/月频目标变成每日恒定权重再平衡。只有出现拒单或部分成交时，未完成目标才延续到后续交易日；已完成证券不会因价格波动被重新纳入追单。当日未成交订单不盲目原样挂到次日；系统从“未完成目标 + 实际持仓 + 新交易日因果价格”重新计算净订单。这避免停牌、涨跌停或部分成交后旧订单与新组合状态冲突。冻结策略名为 `cancel_and_rebuild_from_active_target`。

## 公司行为

原始层保留 Tushare `dividend` 接口的预案、股东大会和实施版本。curated 层仅接受状态精确等于 `实施`的记录，`停止实施` 必须排除，不得使用子串包含判断。对同证券、同报告期保留供应商的合法版本链，只去除逐字段完全重复的行，再选出最新实施版本，并将同一供应商行拆成独立的现金与送股事件。

正式回测不只审计“返回了哪些公司行为”，还审计“查过哪些证券”。公司行为产物必须与同一 P0.5 可交易域绑定，写入冻结查询集合、原始快照 SHA-256 及 `query_coverage = 1.0`；空返回也是有效查询证据。任一标的未查询、查询失败、哈希不一致或产物未晋级，都禁止正式 P0.6.3 晋级。

- `announcement_at`：实施公告日 16:00 上海时间；
- `available_at`：其后第一个被 P0.5 覆盖的交易日 08:40；
- 若无法证明事件在除权除息开盘前可知，则 fail closed；
- 除权日早于平台上市日的行为明确记为上市前事件并排除，不得借此给上市后持仓补股或补现金；
- 现金分红使用税前每股金额。默认税率显式冻结为 0，因投资者类型和持有期间相关的税务不得用隐式猜测代替；实盘前必须加入匹配账户的独立税收策略。

送股、转增股产生的不足一股权益按冻结策略 `floor_zero_value_v1` 向下取整，不虚构现金补偿，并在公司行为账本记录丢弃数量。[中国结算深圳分公司《证券发行人业务指南》](https://www.chinaclear.cn/zdjs/szfgsgg/202510/c6741ed354d7425396db22acceaf6a3e/files/%E9%99%84%E6%B3%A8%E5%8F%82%E8%80%832%EF%BC%9A%E4%B8%AD%E5%9B%BD%E8%AF%81%E5%88%B8%E7%99%BB%E8%AE%B0%E7%BB%93%E7%AE%97%E6%9C%89%E9%99%90%E8%B4%A3%E4%BB%BB%E5%85%AC%E5%8F%B8%E6%B7%B1%E5%9C%B3%E5%88%86%E5%85%AC%E5%8F%B8%E8%AF%81%E5%88%B8%E5%8F%91%E8%A1%8C%E4%BA%BA%E4%B8%9A%E5%8A%A1%E6%8C%87%E5%8D%97.pdf) 规定的碎股分配需要全部投资者的小数部分排序，并在并列时使用随机机制；单账户历史回测无法重建该全局状态，因此采用可复现且保守的下取整口径。

已持有证券到达 P0.5 冻结的退市日且无可证明的退市对价时，按 `zero_recovery_at_delist_open_v1` 在当日开盘将持仓减记为零。不得把退市日提前以消除陈旧估值，实际正持仓减记数与零持仓终止事件分开统计。

配股不会被自动认购，必须以显式订单表达。未知行为类型直接拒绝。

## 容量和情景

每个有效目标日都保存时变容量：

- 订单容量 = 滞后流动性的最小值 × 参与率 × 流动性折扣；
- 持仓容量同时受自由流通市值上限和压力退出金额上限约束；
- 策略容量是订单容量与持仓容量的较小值；
- 任一必要容量字段缺失时容量归零，不用未来值或横截面均值填补。

四套情景使用完全独立的账本：`base_open`、`conservative_open`、`delay_one_session`和 `commission_aware_open`。保守情景的 0.5% 参与率和 50% 流动性折扣同时进入成交与容量估算，不会只修改报表标签。

`build-backtest` 按输入哈希、冻结参数和实现树哈希生成内容寻址的 `artifact_id`，输出：

- `daily_nav.parquet`；
- `daily_positions.parquet`；
- `stale_valuation_bounds.parquet`；
- `target_weights.parquet`；

同一输入重跑必须返回同一产物目录；若同 ID 下内容不同则拒绝覆盖。

## 硬晋级门禁

以下任一失败都不允许产物标记为通过：

- 同情景、同日净值重复；
- 负现金、负 NAV 或负持仓；
- NAV 与现金、持仓市值、应收股息无法勾稽；
- 目标权重突破现金缓冲；
- 成交超出金额参与率、自由流通盘或压力退出天数；
- P0.5 未晋级或其 Parquet SHA-256 与 manifest 不一致；
- 正式公司行为产物与 P0.5 查询域不一致、查询覆盖率小于 100% 或未晋级；
- 超限陈旧持仓的末价/零价两端点缺失、重复、数值不一致；
- 任一执行情景、任一交易日的 `bound_width_pp` 超过冻结容忍度。

## 已知边界

- 滑点与冲击系数在导入真实券商回报前仍是冻结的研究假设；
- 日线只能对停牌和一字涨跌停做保守处理，不能还原盘中开板时间和排队；
- 股息税、融资融券、股指期货保证金、跨市场现金结算不在本阶段；
- 本层接受外部冻结目标权重，alpha 因子的 PIT 去重、中性化和多因子合成属于后续阶段。
