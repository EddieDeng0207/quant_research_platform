# 可复现研究与交付标准 v1

## 目标

任何进入候选池的研究都必须允许未来的研究主管在不依赖作者记忆的情况下：

1. 理解研究假设和经济逻辑；
2. 核对数据来源、知识时间与处理口径；
3. 查看完整代码、配置、测试和失败记录；
4. 在具备相同数据授权时一键重建结果；
5. 在无法分发原始数据时通过清单、哈希和冻结产物完成审计。

## 数据层硬性要求

- raw 数据只追加、不覆盖；每个文件必须登记 SHA-256。
- 数据密钥不进入代码、配置快照、日志或交付包。
- 每次请求记录供应商、端点、非敏感参数、字段、行数、单位转换和写入时间。
- 行情保存未复权价格与独立复权因子；复权序列在 curated 层生成。
- 财务与事件数据同时保留事件所属期、公告日、实际公告日和系统可用日。
- 全市场截面优先按交易日下载，便于证明覆盖率和发现缺口。
- 跨源修复不能静默发生，必须有修复审批与来源记录。
- 可交易性产物必须引用历史股票池、行情、涨跌停、停复牌、ST、证券主数据与代码映射的精确 raw 文件及 SHA-256。
- 证券代码变更不得改写历史 raw；必须同时保留稳定身份、当时有效代码和供应商原代码，并冻结生效政策版本。
- 同一输入、规范、代码树和参数必须产生同一 artifact ID 与逻辑数据哈希；实现代码变化必须改变产物身份。
- 执行层必须冻结原始订单、初始现金、费用政策、成交容量、滑点模型、P0.5 输入及实现代码哈希。
- 回测必须保留全部拒单和部分成交；不得删除涨跌停、停牌、T+1、现金不足或流动性不足的订单后重新计算绩效。
- 当日开盘容量只能使用下单时已知的滞后流动性，禁止使用当日完整成交量构造无前视的假象。
- 组合回测必须保存逐日 NAV、持仓、目标、订单、成交、公司行为账本、时变容量与全部执行情景，不得只保留净值曲线。
- 现金股息必须分离股权登记、除息应收确认和付息现金入账；应收股息进入 NAV 但不得提前用于买入。
- 自动研究报告只能从已验证哈希的冻结产物生成，不允许手工重输绩效指标。

## 运行层硬性要求

正式运行必须绑定clean Git commit、Git tree和精确依赖锁；只有文件哈希、没有
commit或可恢复源码包的结果不得晋级。探索运行可以保留dirty fingerprint，但
必须标记为不可晋级。版本控制与发布细则见
`docs/version_control_and_release_standard.md`。

每次批次生成：

- `config_snapshot.json`：完整配置；
- `run_manifest.json`：Python、平台、依赖版本、源代码哈希、起止时间和状态；
- `source_snapshot/`：本次运行使用的可执行源码、非敏感规范文件和逐文件 SHA-256；
- `events.jsonl`：逐任务请求、重试、成功、跳过和失败事件；
- `summary.json`：文件数、行数、检查点和失败任务；
- checkpoint：每个成功任务后原子更新，允许安全续跑。

失败运行不得删除。修复后重新运行必须产生新的 run ID，同时引用原检查点。

## 研究层硬性要求

- 明确冻结训练、验证和最终保留区间。
- 记录所有尝试，包括无效和负面结果。
- 因子报告至少包含覆盖率、分布、IC/Rank IC、分层收益、单调性、衰减、换手、成本、年度稳定性和行业暴露。
- 策略报告至少包含净值、超额、回撤、风险暴露、归因、换手、成本、容量和压力测试。
- Agent 只能在协议允许的数据区间迭代，不能自行解锁最终保留集或覆盖基准结果。

## 交付等级

1. **完整复现**：凭相同授权重新下载数据并一键运行。
2. **快照复现**：在许可允许时使用冻结数据快照运行。
3. **审计复现**：使用数据清单、哈希、统计摘要、代码和冻结结果验证全过程。

正式对外交付前必须另行核对数据供应商关于原始数据和派生数据的分发条款。
